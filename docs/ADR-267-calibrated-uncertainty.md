# ADR 267: Calibrated uncertainty and abstention

Status: Accepted

Date: 2026-08-21

## Context

`FieldInference.confidence` is a scalar generated by a model or rule. It does not identify a calibration population, coverage target, out of distribution condition, or reason to withhold an answer. Treating it as a calibrated probability creates safety and governance risk.

## Decision

Keep `FieldInference` unchanged for source compatibility. Add composable core types for prediction sets, prediction intervals, calibration context, out of distribution score, and abstention reason. `CalibratedInference` wraps the legacy inference in an `UncertaintyEnvelope`.

Add `rufield-uncertainty` with a model independent binary split conformal classifier. It uses the finite sample corrected empirical quantile and returns a set of possible labels. It abstains when the set is ambiguous or the input exceeds the configured out of distribution threshold.

The calibrator binds nonempty model, calibration, and domain identities. At inference time only the configured positive and negative labels are accepted. Positive label confidence is interpreted as positive probability; negative label confidence maps to one minus confidence. Unknown labels and model or calibration lineage mismatches fail closed.

Conformal coverage is conditional on exchangeability between calibration and deployment examples. It is measured per held out domain and is never inferred from the algorithm alone.

## Inputs

1. Labeled positive probabilities from a calibration split.
2. Alpha, minimum calibration sample count, nonempty domain, model identity, calibration identity, and calibration time.
3. A legacy `FieldInference` and independently computed out of distribution score.

## Outputs

1. A finite sample corrected nonconformity threshold.
2. A prediction set with an explicit coverage target.
3. A calibrated inference with calibration context, out of distribution score, and optional abstention reason.
4. Empirical coverage on an independent evaluation split.

## Assumptions

1. Probabilities are finite and inside the unit interval.
2. Calibration labels are independent of model training labels.
3. Calibration and evaluation examples are exchangeable within the declared domain.
4. The out of distribution detector is evaluated separately.

## Alternatives considered

1. Add optional uncertainty fields directly to `FieldInference`. Rejected because Rust struct literals in existing consumers would break even with Serde defaults.
2. Temperature scaling only. Rejected as the sole interface because it still emits one answer and provides no set valued abstention contract.
3. Bayesian model specific uncertainty. Deferred because RuField supports multiple model and rule backends.

## Migration

Legacy producers continue emitting `FieldInference`. New consumers opt into `CalibratedInference`. Fusion implementations can add calibrated output methods later without changing the existing `FusionEngine` trait.

## Rollback

Consumers can discard the uncertainty wrapper and recover the original inference exactly. Removing the new crate does not alter v0.1 serialization.

## Acceptance

The conformance calibration fixture must meet its 90 percent coverage target on a separate fixture split, reject insufficient calibration data, map negative confidence correctly, reject unknown labels and lineage mismatches, and force abstention when the out of distribution score crosses policy.
