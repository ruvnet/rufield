# RuField implementation review, 12 October 2026

Scope: README visualization, installable Claude Code workflows, viewer configuration and upstream ingestion. This was a focused source and regression review, not a certification or exhaustive dependency audit.

## Changes and evidence

| Finding | Impact | Fix and regression |
|---|---|---|
| Each SSE chunk was decoded with lossy UTF8 | A split multibyte sensor string could be corrupted before signature verification | Retain bytes until complete event; test every split across LF, CRLF and CR |
| Only LF blank lines were recognized | CRLF streams could stall and accumulate memory | Stateful CR/LF decoder with framing regressions |
| SSE and polling responses had no retained-size ceiling | Upstream input could grow memory without a bound | 4 MiB event/response cap before parsing; oversized SSE and actual loopback HTTP tests |
| Unknown CLI flags and malformed integers fell back silently | Operator intent could be ignored, including misspelled source selection | Reject invalid arguments and environment values; process-level tests and help output |
| A live router without an ingest channel entered the synthetic stream branch | The selected mode and displayed stream could disagree | Live-only branch even when disconnected; HTTP stream regression |

Two equivalent hex parsing expressions were updated for current Clippy. No trust policy was weakened. Replay persistence across viewer restarts remains an explicitly documented integration requirement.

## User-facing additions

Four self-contained animated SVGs explain sensing, the evidence pipeline, privacy classes and evidence modes. They include accessible titles/descriptions, static fallback content and reduced-motion CSS. Regenerate with `python3 scripts/generate-readme-svg.py`. XML parsing and static render inspection passed; browser animation inspection could not run because the browser download was invalid in this environment.

The `rufield` Claude plugin supplies demo, replay and audit skills, packaged in a local-source marketplace. It has no automatic hooks, MCP servers or credential changes. The workflows use actual repository APIs and commands, distinguish installed plugin cache from source checkout, and preserve synthetic versus physical evidence claims.

## Validation

Linux, Rust 1.99.0. The full `harness/run-evidence-gate.sh` passed 299 Rust tests and 9 Node tests, plus format and strict Clippy checks. One subsequent oversized HTTP response regression also passed, bringing the final Rust test inventory to 300. `cargo fmt --all -- --check` and `git diff --check` passed after that addition.

`python3 scripts/verify-e2e.py` passed against built binaries: same-seed semantic benchmark reports match (latency excluded), privacy violations equal zero, provenance coverage equals 100%, viewer HTTP endpoints respond, and SSE completes meta → frame → done. The script manages only its own local process.

`python3 scripts/validate-plugin.py` passed. Claude Code 2.1.296 `plugin validate` accepted both marketplace and plugin with no warnings. Marketplace registration, plugin installation and enabled status also passed in an isolated temporary Claude configuration. An authenticated model session and physical sensors are separate validation surfaces; no physical accuracy or production deployment claim is made.

## Acceptance

From this checkout, run:

```sh
python3 scripts/validate-plugin.py
cargo build --locked -p rufield-bench -p rufield-viewer
python3 scripts/verify-e2e.py
sh harness/run-evidence-gate.sh
```

Then install the marketplace/plugin and exercise `/rufield:demo` in Claude Code against this checkout. Physical promotion still requires the independent evidence artifacts specified by the existing evidence gate.
